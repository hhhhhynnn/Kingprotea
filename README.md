# 帝王花 · 桌面挂件

King Protea 在 Windows 桌面边缘爬来爬去的小挂件。透明背景、置顶，可以同时放
最多 10 只，大小和速度实时可调。

![截图](docs/screenshot.png)

**只在 Windows 10 / 11 上能跑。** 用到了色键透明窗口、全局热键、DWM 标题栏
染色，都是 Windows 专有接口，macOS 和 Linux 没有对应实现。

## 下载即用（不需要装 Python）

到 [Releases](../../releases) 下载 `KingProtea-win64.zip`，解压，双击
`KingProtea.exe` 就能跑。压缩包 27 MB，解压后 48 MB，Python 和依赖都在里面。

> 第一次运行 Windows SmartScreen 可能拦一下，提示"已保护你的电脑"——因为这个
> exe 没有花钱买代码签名证书。点"更多信息"→"仍要运行"即可。介意的话就用下面的
> 源码方式跑。

## 从源码运行

需要 **Python 3.8 或更高**，装一个依赖：

```bash
pip install Pillow
```

然后双击 **启动.bat**，弹出控制窗口，挂件同时开始爬。
（脚本会自动找 `pyw` / `pythonw` / `py` / `python`，找不到会提示。）

tkinter 是标准库自带的。如果是从 python.org 装的 Python，安装时勾选了
"tcl/tk and IDLE"（默认勾选）就有；Anaconda 也自带。除 Pillow 外没有别的依赖。


三个滑块都是实时生效的：

| 滑块 | 范围 | 默认 |
| --- | --- | --- |
| 数量 | 1 ~ 10 只 | 1 |
| 大小 | 80 ~ 600 px（身体长度） | 200 |
| 速度 | 0.3 ~ 6.0 倍 | 1.0 |

速度 1.0 时位移和爬行动作严格同步，不会有滑步感；往两边调都会开始有一点，
调到 6 倍就是明显在飘了——想要快又不飘，把大小一起调大，两者是联动的。

大小超过 507px 会开始放大插值（素材原生就是 507px 一帧），600 那一档略糊。

停止：控制窗口的**退出**按钮、直接关掉窗口，或者 **Ctrl+Alt+Q** 全局热键。
暂停用**暂停**按钮或 **Ctrl+Alt+P**。

控制窗口最小化以后挂件照常爬。右键点她可以把控制窗口叫回来，左键点她是暂停。
透明区域点不到，鼠标会穿过去落到底下的窗口上，只有她的身体能点中。

启动.bat 后面也可以直接给初始值：`启动.bat --count 5 --size 400 --speed 2`。

## 屏幕适配

- **任何分辨率都能用**。路线是按当前屏幕尺寸算出来的，不是写死的坐标。
  1366×768、4K、带鱼屏、竖屏都验过，贴边正常。
- **中途换分辨率没问题**。程序每秒检查一次屏幕尺寸，发现变了就重算路线、
  让所有挂件按新边界重新进场。换显示器、插拔扩展坞、改缩放都能自动跟上。
- **高 DPI 缩放已适配**。窗口尺寸按系统 DPI 等比放大，125% / 150% / 200%
  下控件和文字的比例一致。
- **多显示器只用主显示器**。她只在主屏的四条边上爬，不会跑到副屏去。

## 怎么爬

沿着屏幕的某一条边直线爬过去，**不拐弯**。整个身子爬出屏幕后，随机换一个角落、
随机换一个方向重新钻进来。比如从左下角沿左边向上爬出去之后，下一趟可能从右下角
冒出来沿底边向左爬。

四个角各连着两条边，所以一共八种走法，每趟随机挑一种（不会连着走同一种）。
爬出去到再出现之间会随机歇 1.5 ~ 5 秒——想让她们不间断地爬，把 `console.py`
顶部的 `WAIT_MIN, WAIT_MAX` 改成 `0, 0` 就行。


## 实现要点

- **原动画是平铺循环的**：她在 512×512 画布里每帧向左移 4 像素，128 帧正好走完
  512 首尾相接，所以有的帧里屁股在左边、脑袋从右边探进来。做挂件需要"原地爬、
  窗口动"，先把每帧反向平移 `4×帧号` 像素复位，再取所有帧的并集边框裁出精灵。
  复位后每帧都是完整不断裂的单个身影。窗口里那条预览就是复位后的原样。
- **去掉了 GIF 抠图残留的黑边**：源文件是 GIF 转的 WebP，GIF 只有 1 位透明度，
  原本半透明的抗锯齿边被压成了不透明的暗色，放大后就是一圈明显的像素黑边。
  实测最外一圈亮度只有 145、发黑像素占 27%，而第二圈是 192 / 0.6%。
  处理办法是丢掉最外圈不可信的颜色、用内层重算，再把颜色向透明区外扩 6 圈——
  外扩是因为 PIL 缩放 RGBA 时 RGB 和 alpha 各自独立插值，不外扩的话透明区那片
  近黑色（原本均值 22,21,23）会被拖进边缘。处理后最外圈变成 190 / 0.6%。
  alpha 通道全程没动。
- **八条路线**：`console.py` 里的 `routes()` 把(趴在哪条边、朝哪个方向)列成八条。
  朝向角决定贴哪条边，镜像与否决定朝向；入场时头刚好顶在角上、身子还在屏幕外，
  尾巴越过对角就算爬完。

实测：默认 1 只 200px 约 94MB 内存、满帧；拉到极限 10 只 600px 约 208MB、20fps
（瓶颈是同时移动 10 个大号透明窗口的合成开销，把缓存上限从 60MB 提到 400MB
只快 0.7fps，所以没必要多占内存）。
